\section{Related Work}\label{sec:related}

\paragraph{Attacks and model-based defences.} Liu et al.~\cite{liu2024formalizing} formalise prompt injection attacks
and defences, and InjecAgent~\cite{zhan2024injecagent} and AgentDojo~\cite{debenedetti2024agentdojo} measure attacks on
tool-using agents. These benchmarks are in English, although LLM safety is weaker in low-resource
languages~\cite{deng2024multijail}. Adaptive attacks have also broken many published defences~\cite{zhan2025adaptive}.
Among model-based defences, Spotlighting~\cite{hines2024spotlighting} marks untrusted data, sandwich prompting repeats
the request after every observation, and SecAlign~\cite{chen2025secalign} fine-tunes the model to separate instructions
from data. Prompt Guard~2~\cite{meta2025promptguard2} screens inputs with a classifier, while MELON~\cite{zhu2025melon}
compares the actions of a run with those of a re-run with the request masked. These approaches depend on how the model
or the classifier behaves on the attack data, a dependence that enforcement at the broker avoids.

\paragraph{Policy enforcement outside the model.} Progent~\cite{shi2025progent} applies privilege policies to tool
calls, and ClawGuard~\cite{zhao2026clawguard} lets a model derive access rules from the user request.
FIDES~\cite{costa2025fides} attaches trust and confidentiality labels to data and propagates them across calls.
CaMeL~\cite{debenedetti2026camel} separates control flow from untrusted data with a dedicated interpreter and attaches
capabilities to every value. CapLite~\cite{xu2026caplite}, released concurrently, derives its policy from tool schemas,
commits write calls before reading tool results, and admits a write only if the arguments that decide what it affects
are stated in the request. Beurer-Kellner et al.~\cite{beurerkellner2025patterns} systematise such design patterns.
Structured policies and safety proofs are thus not new in themselves. \ours{} differs in keeping the ReAct loop
unchanged and checking each call at the broker, instead of rewriting the agent as an interpreter like CaMeL or fixing
the write calls before reading data like CapLite. Its policy is extracted deterministically from the user request and
handles negation in Vietnamese with and without diacritics and in English, whereas ClawGuard lets a model write the
rules and Progent relies on hand-written rules. Sensitivity is assigned to each value by type at the broker rather than
propagated through every computation as in FIDES, which is cheaper but protects values only within the class of
transformations stated in Section~\ref{sec:formal}.
