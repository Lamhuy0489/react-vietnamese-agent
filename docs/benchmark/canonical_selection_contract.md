# Whole-pool selection and grouped split v1

Scope: Phase 3 canonical admission for variant authoring, not final release or
model evaluation. Inputs are the hash-bound boundary receipt and its eight
unsplit batches (72 stored candidates); old data, source and receipts stay intact.
The two previously merged cases remain regression inputs, not quota members.

## Review gate

Review all public tasks, attack/benign texts and existing per-pair rationales.
Record a scenario-specific whole-pool distinction for every stored candidate.
Retain 70 task/authorization scenarios, not 70 unrelated abstract mechanisms.
Use assistant self-review under the recorded owner waiver; never label it
independent human review. Keep all conservative semantic/template edges,
including edges through merged cases. Exact shared source IDs, private artifact
values and mock destinations are additional leakage links. Normalized duplicate
attack texts cannot be admitted as separate representatives.

Revalidate schema/identity, complete review coverage, immutable input hashes,
paired reference evidence, source reachability and safe utility. Reused Replay
evidence is not new inference. Bounded exact/typed scorers are not general
semantic entailment or comprehensive attack-success evaluators.

## Split rule, before assignment or variants

Keep complete connected components together. Enumerate all assignments totaling
40 Dev and 30 Test. Minimize, lexicographically:

1. Sum of absolute deviations from the 4/7 Dev share for category and source.
2. The same deviation sum for target sink and reference-path complexity.
3. SHA256 of fixed seed `phase3-canonical-selection-v1` plus sorted Dev IDs.

Use integer loss `abs(7 * dev_count - 4 * total_count)` (seven times the
family-count deviation); no floating-point comparison or model outcomes.
Complexity is the safe reference action count, an observable proxy, not empirical
difficulty. Target sink derives from the prohibited reference operation; report
its derivation and limits. Report all strata including zero-count cells.

The 25-member business group stays together. It contains 12 of 15 tool-output
poisoning scenarios: ideal stratification is impossible. No hidden balance
threshold is introduced, no grouping edge is removed, and this limitation must
appear beside results. Selection supports grouped evaluation, not category-wise
representativeness. If no exact grouped 40/30 solution exists, fail closed.

Write a separate immutable selection manifest with canonical/family IDs, group,
paired IDs, source references and hashes. Do not alter `split=unassigned` in old
snapshots. This manifest is authoritative for the new selection only. Generate
five reviewed paired variants *after* assignment. Test is not sealed until all
variant, replay, mapping and release checks pass. No Test model runs/tuning.

## Acceptance boundaries

`canonical_authoring_admitted` and `canonical_split_valid` may pass separately
from `phase3_accepted`, which remains false until 350+350 reviewed executable
variants, release integration and a complete Test seal exist. The selection
receipt alone must never satisfy the Phase 3 closure gate.
