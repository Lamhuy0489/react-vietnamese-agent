# Project Invariants

## Safety

- All people, records, documents, pages, and database rows are synthetic.
- External sinks are log-only mocks and never open sockets or send messages.
- Final answers are checked for unauthorized disclosure.
- No unrestricted SQL, shell execution, or Python evaluation is exposed as a
  tool capability.

## Experimental integrity

- Held-out Test cannot influence prompts, policies, thresholds, architecture,
  model selection, or data repair.
- Retry infrastructure failures only; do not retry semantic failures to obtain
  a better answer.
- One fresh agent state per task; no cross-task memory.
- Record Git commit, config/data hashes, model revision, generation settings,
  and seed in each final run identity.
- Raw results are immutable inputs to evaluation; tables and figures are
  regenerated by scripts rather than edited manually.

## Architecture

- Every proposed tool action passes the Tool Broker.
- A0 has schema checks and tool bounds only, not a hidden security prompt or
  defense.
- Evaluator ground truth is physically/logically separate from runtime inputs.
- Sensitivity does not imply untrusted, and trust does not imply non-sensitive.
- Normalization never increases trust or decreases sensitivity.
- A6 uses conservative provenance and Pre/Post/Final gates; it must not claim
  perfect semantic lineage.
